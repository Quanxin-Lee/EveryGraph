# EveryGraph functional scope

## 1. Authority, evidence, and traceability

This is a planning specification, not an implementation report. The current user instruction requires all functional capabilities in both inventories, plus EveryGraph additions. Their older non-requirement disclaimers describe the inventories' original purpose; they do not override this instruction. Both source files remain unchanged. No feature is claimed delivered.

`feature-traceability.csv` contains 428 rows: one for each of 215 ORG and 124 DG IDs, then 71 EG-REL release children (55 Origin and 16 DataGraph), then 18 EG-ADD additions. Capabilities retain the original English titles; release rows without English titles receive descriptive English translations. Source paths are repository-relative, and source lines are one-based physical lines pointing to the actual inventory table row or the addition row below. Release children name their parents in acceptance text; they are not additional implementations of already-covered behavior. Origin release capabilities already fully represented, such as Flash Fill, periodic import, Graphical Summary, mirror columns, MHTML, Decision Tree and Data Factory, retain their original requirements without unnecessary duplicate children.

The evidence baseline is the inventories, not newly verified vendor behavior: Origin/OriginPro 2026 and 2026b, Core/Pro/App/Connector distinctions, uncertain third-party licenses and COM availability; DataGraph 5.5 build 68 versus its 5.4 manual, product-page-only claims, application-resource-only database/cloud entries, and unavailable 5.5 release notes (403). DataGraph's coverage summary says nine 5.4 changes, but its actual release table has ten; all ten are required. Origin SR1/SR2 changes and unlisted DataGraph 5.5 changes remain discovery obligations. Price, audience size, version metadata, and vendor platform statements are evidence constraints, not user features or EveryGraph targets.

`planned` means required with an intended delivery route; `unresolved` means required but its detailed scope, evidence, or compatibility feasibility remains open. Delivery classifications: `native` EveryGraph behavior; `adapter` an explicit format/service boundary; `platform-specific` OS integration with stated availability; `research-gate` feasibility/licensing/behavior investigation before a support claim; `constraint` evidence, catalog, platform, or performance obligation. Mixed rows remain open until every component passes; an open proprietary component cannot be hidden by shipping the open components.

## 2. Architecture and dependency schedule

The architecture is being designed: a modular monolith with explicit module contracts, not prematurely distributed services. A GUI-independent application command API owns validation, transactions, authorization, progress, cancellation, undo, and replay. Immutable columnar data versions and a dependency DAG connect imports, formulas, variables, analyses, reports, and scenes. Views never silently overwrite source data. A backend-neutral 2D scene/render interface separates scientific coordinates from UI and output devices. Future grid, image, 3D, and GIS engines attach through interfaces; their optional deployment does not make required capabilities optional in scope.

Python and native extensions execute in trusted, isolated workers with capability-brokered file/network/process access, explicit consent, resource limits, and versioned interchange. Process separation alone is not a claim of a secure sandbox. AI is provider-neutral and uses the same commands as GUI and automation; it does not mutate internal state directly.

| Phase | Required exit and prerequisites |
|---|---|
| P0 | Evidence ledger, catalog-expansion obligations, compatibility questions, and acceptance governance; unresolved catalogs block parity acceptance, not delivery of this plan. |
| P1 | macOS Apple Silicon shell and command/kernel contracts, transactional cancellation, data/scene/worker interfaces; Windows x64 qualification is a deferred later gate; depends on P0 decisions. |
| P2 | Typed data, imports, native persistence, formulas, immutable versions and DAG; depends on P1. |
| P3 | 2D editing, basic export, annotations, variables, and interactive exploration; depends on P2 and scene contracts. |
| P4 | Scientific analysis, advanced statistics, fitting, peaks, signals, and validated result schemas; depends on P2/P3. |
| P5 | AI assistance atop validated commands; depends on P1–P4 and privacy controls. |
| P6 | Python/plugins, connectors, advanced reporting/animation, automation, compatibility packs; depends on relevant P2–P5 contracts. |
| P7 | Profiled performance, advanced matrices, 3D/GIS/image engines, domain completeness and ecosystem; depends on P2–P4/P6 interfaces and evidence. |

CSV phase means the latest required completion gate for that row, not its start date. Mixed families explicitly deliver their 1D/tabular/2D components earlier: wavelets/convolution in P4 before their 2D matrix extensions in P7; tabular views in P2 before full matrix/image window workflows in P7; static reporting primitives in P3/P4 before advanced reporting in P6. P6 integration does not defer scientific algorithms from P4, and P7 specialization does not block ordinary P3 heatmaps. Native persistence is P2 even though foreign project compatibility is P6. P7 profiling follows earlier correctness and responsiveness budgets. Platform sequencing follows [ADR-0005](../decisions/ADR-0005-platform-sequencing.md): macOS Apple Silicon is the only active qualification target; Windows x64 is a deferred later gate whose requirements and platform interfaces remain, and no Windows implementation, evidence, packaging or support claim is authorized until a Windows x64 host or authorized CI qualifies it.

## 3. Shared acceptance and completeness gates

Each CSV acceptance names a concrete operation, result, or failure. The following suites apply in addition, not as substitutes for capability-specific tests:

- **DATA:** golden typed fixtures including missing/NaN/infinite values, Unicode, locale, timestamps, units and metadata; deterministic row identity, immutable originals, formula/DAG invalidation, cycle rejection, undo, and reopen checks.
- **UI:** execute through commands and GUI; keyboard navigation, focus and assistive-technology labels; persisted settings, undo/redo and dependent-view refresh. Current acceptance covers macOS Apple Silicon only; Windows x64 is a deferred gate that requires the same UI suite on a Windows host before any cross-platform claim, and Linux, macOS Intel and Windows ARM64 are later qualification targets. Minimum versions are explicit P0/P1 decisions, not inherited vendor minima.
- **PLOT:** named example scenes with checked data-to-coordinate mappings, axis transforms, legends, labels, clipping, layer order, dimensions, vector semantics and raster reference images; compare with declared font/antialias tolerances, not arbitrary pixel identity across systems.
- **NUM:** published/reference datasets and analytic synthetic cases; algorithm/options, missing-data policy, weights, seeds, convergence and conditioning recorded; absolute/relative tolerances, confidence intervals, residuals and failure diagnostics fixed before evaluation. Cross-check independent trusted implementations, not just agreement between our UI and kernel.
- **IO:** versioned format corpus, import/export direction, locale, precision, metadata and unsupported constructs; round-trip where promised, external-reader verification, malformed-file limits and explicit loss reports. Never execute macros or imported code implicitly.
- **AUTO:** headless/GUI equivalent command results, deterministic job manifests, partial-failure reporting, cancellation and permissions; captured clocks/seeds and declared nondeterminism.
- **PERF:** published dataset/hardware/backend/build, warm/cold cache, latency percentiles, peak memory, cancellation and full-resolution export accuracy. Set measured budgets before sign-off; vendor speedups and “millions of rows” are not measured EveryGraph results.

**Catalog expansion is a blocking acceptance gate.** Coverage of 339 IDs does not establish coverage of 100+ graph types, 30+ import formats, nearly 200 fitting functions, 25+ peak functions, 17 export formats, or unnamed options. At P0 create a versioned, reviewable enumeration within this planning scope/traceability pair, using the inventories' registered manuals/catalogs as follow-up evidence. For every named family example and subsequently discovered item, record a stable child ID, exact method/format variant, parameters, prerequisites, license, delivery, fixtures, expected outputs and uncertainty. Include full function/operator/constant libraries, Plot Action actions, report/batch variants, Apps, graph galleries, RS/GIS operations, import versions and image-drop formats. Unknown lists remain explicitly open; a count or umbrella test cannot close them. Expansion continues until every source-intended family is reconciled, with no silent exclusion of difficult variants. The present deliverables plan that obligation rather than fabricate missing catalog names.

## 4. Functional families

### Workspace, data, formulas, and variables

Provide Project Explorer/Browser, folders/search (including project files and data cells), Object Manager, ordered graph commands, graph thumbnails/groups, workbook/worksheet, matrix, graph, layout, Notes and image documents, docked/floating multi-monitor windows, dark UI independent of plot colors, toolbars/mini-controls, focus mode, preferences, examples, comments/pop-up notes, repeat/reopen and undo/redo. QuickGraph previews select count bars, histograms, regression scatter or matrix-style summaries by input shape; Loupe magnifies without changing axes, Hover reads points/bars/boxes. “Screen Reader” in ORG means coordinate readout, distinct from accessibility screen readers.

Data includes numeric/text/date/IEEE binary columns; roles, units, widths/heights, metadata, headers and formatting; entry, selection, column lists/groups and relative/absolute references. Preserve missing versus zero and display versus stored precision. Support cell/column/text expressions, row numbers, library functions/operators/constants, command-output columns, Plot Action, category interpolation, Map/defaults, Mask, Redirect aliases, mirror columns sharing storage, and propagating columns/formulas across sheets. Provide Excel-formula import with supported-function diagnostics, error highlighting/find-replace, Flash Fill and Smart Formula, comma decimals, local function-name copying (local versus localized semantics unresolved), and structured Life Science tables with subject/treatment/replicate metadata.

Prepare data with sort/filter, worksheet query, merge/append/split/transpose, pivot, stack/unstack, find/replace, conditional extraction, duplicate/row/column reduction, evenly spaced X and grouped reduction. Generate row numbers, uniform/normal random data, sequences, arbitrary numbers, dates, times and text. Recalculation supports reopened parameters, auto/manual modes, analysis-lock visibility, input-triggered DAG updates and copying operations to other datasets.

Variables comprise Slider/integer steps, Value/fine adjustment, Text, Number from Command, Number from Column (sum/max/mean/range/count/standard deviation), Expression/local variables, Font, Color Scheme, Marker Scheme, Current Time/time zones/increments, Text Menu and dynamic Text Set from Column. Changes propagate through masks, labels, plots and analyses; cycles and ambiguous names produce diagnostics.

### Input, persistence, output, and integration

Import ASCII/CSV/TXT with delimiter/header/skip/region rules; automatic tab/comma/semicolon/pipe/space parsing; clipboard, Paste Special (decimal conventions, transpose, trim), full/partial files, reusable Import Special records/subheaders/end-tags/masks, drag/drop data and images. Plan XLS/XLSX/XLSM without installed Excel; MATLAB including v4 and explicit other-version discovery; NetCDF including v3 flattening and dimension order; GeoTIFF, legacy Plot, local/URL JSON, XML/Unix timestamps, binary formats and Prism. SQL, ADO/ODBC, local/network/Web/cloud sources support credentials, refresh/re-import, periodic scheduling from five seconds to three days, and disconnect-after-import. Minitab, Ivium, RPC3 and DMD require versioned connector research, not guessed decoders.

Native projects support atomic save/save-as, package and single-file representations, protection, recovery and migration. Foreign OPJ/OPJU and `.dgraph` remain separate gates. Output includes selected/all data as delimited text, XLSX/Note sheets and matrix interchange; PDF/EPS/SVG/EMF/DTG and PNG/TIFF/JPEG/JPG/BMP; alpha, resolution, page dimensions, multi-format clipboard, element-only copies, layout/flagged/project batch export and deterministic naming. EPS transparency must be flattened with a disclosed policy or rejected. Plan printing, OS sharing/Mail, embedding, PowerPoint/Word, HTML/EMF tables and Notes MHTML; availability differs by platform and external application.

### 2D visualization, editing, and interaction

Cover lines/scatter/line-symbol/step/smooth curves; numeric/date bars, grouped/stacked bars and areas in both orientations; connecting bars, pies/doughnuts/multiple pies, waterfall, shared/independent multi-X/Y axes and panels; grouped/categorical/hierarchical plots. Include histograms/count/probability/density/CDF/PDF, boxes/distributions/violin/dots/confidence intervals, probability/control/Pareto charts; OHLC/candlesticks, connecting point pairs, pivot summaries, regular-grid scalar fields, XYZ contours/heatmaps/color blocks and overlaid contours. Specialized families include Gantt, arrow, network/correlation, Before-After, maps, polar/vector/ternary/triangular, hydrochemistry, profile, function and image graphs; DataGraph adds spider and mosaic. Graph Maker supports drag/drop, grouping/faceting and append modes. Cause-and-effect, frequency, dual-X, stem-and-leaf and individual-value release plots are explicit children. Domain and geographical variants complete at P7, not by renaming generic plots.

Editing includes error bars, labels, trends/references, fill/alpha/pattern/gradient, marker size/shape/color mappings, linear/log/probability/reciprocal/date/time scales, inversion/ranges/ticks/units, grids, zero/reference lines across layers or from column-label rows, axis breaks/buttons, legends/category legends/color ramps, themes/templates/defaults, saved Graph Options, publication sizing/fonts/line widths, panels/insets and current-layer indicators. Annotations cover text/math/image/shape/arrow, anchors/offsets/alignment/snapping, slope, brackets, regions/ranges, extra-unit axes, magnify connectors and anchored/cropped images. Include single-label Lines, Box outlines/point-width bounds, graph-table typography, element masks/axis selectors, mini-axis/slider controls and style context menus.

Exploration covers zoom/pan/reset, coordinate/data readers, non-destructive masks and point edits, ROI extraction, multi-channel Browser Graph, Page/Layer/Plot slicers, and click-event dashboards. DataGraph specialty names and click semantics need evidence refinement, not an assumption of identical vendor commands.

### Scientific methods and interactive Gadgets

Gadgets expose Statistics, Vertical Cursor, Differentiate, Digitizer, FFT, Integration, Interpolate, Intersect, Quick Fit, Quick Peaks, Quick Sigmoidal Fit, Cluster, 2D Integration and Rise Time through shared numerical commands with movable ROI and extractable reports.

Fitting covers linear/polynomial/nonlinear/arbitrary/LOESS and multivariable functions; numeric/graphical ranges; independent/global/concatenate/replicate modes; shared/fixed parameters, bounds/constraints, explicit/implicit functions, LM and ODR with X/Y errors, initialization and reusable function builders/libraries. Results include parameters/uncertainty, Pearson r, residuals/tokens, ANOVA, X/Y prediction and model/dataset comparison with F-test/AIC/BIC. P7 surface fitting adds XYZ/matrix input, multiple/automatic peaks and Z prediction. Function plotting handles discontinuities rather than drawing misleading bridges.

Peaks include manual/automatic baselines (second derivative, XPS, asymmetric least squares), local-max/window/residual/derivative detection, manual insertion, integration windows, height/area/area percentage/centroid/FWHM, 25+ functions subject to catalog expansion, deconvolution, fixed/percentage-limited centers, shared parameters, stepwise fitting, batch themes and reusable Peak Analyzer workflows.

Statistics includes advisers, descriptive row/column statistics, graphical summaries, cross-tabulation and 1D/2D/discrete/grouped frequencies; normality, Grubbs/Dixon Q; normal/Weibull/exponential/Gamma distribution fitting; correlation/partial correlation; one/two-sample, paired and Welch t tests (including row-wise), chi-square, variance, proportion and Poisson-rate tests. Nonparametrics include Wilcoxon, sign, KS, Mann-Whitney, Kruskal-Wallis, Mood median and Friedman. ANOVA includes one/two/three factors and one/two-factor repeated measures, Tukey, Bonferroni, Dunn-Sidak, Fisher LSD, Scheffe and Holm comparisons; summary/diagnostics/power and hypothesis conclusion charts. Multivariate methods include PCA, K-Means, hierarchical clustering, discriminant analysis and PLS; decision trees, logistic regression, random forest and predictive-model advice require leakage-aware validation. Add time-series smoothing/decomposition/forecasting, survival/reliability distributions/identification/overview/life-test planning/lifetime regression, acceptance sampling, stability studies, SPC/control/capability analysis, DOE generation/analysis including binary response, variability, optimal designs and overlaid response contours. Unnamed tests/designs require catalog closure, not invented parity.

Math includes normalization by extrema/mean/area/reference, curve averaging, aligned arithmetic, 1D interpolation/extrapolation (linear/spline), differentiation/integration/extrema; P7 adds 2D/3D interpolation and matrices. Signals include FFT/IFFT, STFT, Hilbert envelope/phase/frequency, 1D/2D CWT/DWT/MDWT/IDWT/denoising, Savitzky-Golay/moving-average/FFT/percentile/Lowess/Loess/binomial smoothing, FFT low/high/band-pass/band-stop/threshold filters, Butterworth/Chebyshev I/II/Elliptic IIR, convolution/correlation, coherence/envelope/decimation and rise time. Matrix FFT/IFFT/filtering and 2D variants finish in P7.

### Advanced engines, reporting, automation, and ecosystem

P7 matrices cover books/sheets/objects, Set Matrix Values, inversion, shrink/expand and custom/median/special filters. 3D covers scatter/surface/contour/bar/waterfall, interpolation and large-grid rendering. RS/GIS covers NetCDF/GeoTIFF processing, geospatial metadata and visualization, with exact operations unresolved. Image capabilities include brightness/contrast/Gamma/hue/invert/saturation/equalization/auto-level/color replacement; alpha blend, XYZ extraction, arithmetic/functions, morphology/pixel logic/background subtraction/replacement; image/data, grayscale, threshold/binary, RGB merge/split, scale/palette conversion; crop/autocrop/flip/offset/resize/rotate/shear; average/clear/edge/Gaussian/median/noise/sharpen/Unsharp Mask and user kernels.

P6 advanced reporting assembles editable linked tables, titles/number styles, rich Notes, image windows, layouts, analysis/graph reports, slides/presentation and external-display selection. Animation variables drive numeric fields with ranges/duration/integer steps, frame preview/management, background movie generation, MP4/Retina export and continued interaction. Batch plotting/import/analysis/result aggregation, analysis templates, Smart Plotting/cloneable templates and Data Factory reuse the command DAG. Python inward/outward APIs, R/Rserve, MATLAB, Mathematica, LabVIEW, shell/parameterized CLI, custom menus/toolbars/scripts, app discovery/search/categories, installation/update/disable/dependencies, development and examples/documentation are required routes, not claims of vendor plugin execution.

## 6. Compatibility, duplication, and open decisions

Compatibility gates distinguish functional equivalence, data interchange, file round-trip, language-source compatibility and binary ABI compatibility. None implies the others. P0 research identifies owners/evidence; P6 packs require legal access to documentation/SDKs, licensing review, versioned fixtures, hostile-input tests, supported-feature matrices, loss diagnostics and external validation. Unavailable rights or specifications leave the gate unresolved, not silently removed or promised solved.

DTG and package/single-file `.dgraph`, OPJ/OPJU including protected files, legacy Plot and Prism require independent read/write/round-trip decisions. LabTalk and Origin C need grammar/runtime/library/API investigations before any source-compatibility claim. XOP-like native binaries are an additional ABI research question, not a claim that either inventory exposes an XOP SDK. Vendor Apps require per-App dependencies/licenses; EveryGraph's own extension marketplace is not vendor-App compatibility. COM/Orglab needs Windows-specific interfaces and licenses; MATLAB/Mathematica/LabVIEW and other licensed engines require installed/authorized products. R/Rserve licensing/deployment is reviewed separately. Native script/CLI equivalents do not promise `dgraph` argument compatibility. Proprietary connector formats and imported Excel formulas need version/function-level scope, diagnostics and safety policies.

Retain duplicate IDs while sharing implementation: ORG-GADGET-014/ORG-SIGNAL-012 rise time; ORG-DATA-012/013 and ORG-PREP-006 mirror/add columns; ORG-DATA-007, ORG-EXPLORE-008, ORG-PREP-001 and DG masks share filtering infrastructure; Digitizer import/Gadget share extraction but have distinct entry points. Pivot, LOESS, fit outputs, report styles, reference lines and export families similarly share commands while retaining source-specific tests. Release-child acceptance can supplement parent tests; it cannot erase either ID.

Remaining decisions are exact unknown catalog membership/options, DataGraph 5.5 behavior and image/SQL/cloud variants, Origin App/Pro/version differences, Life Science layouts, new hypothesis tests, DOE/SPC/reliability variants, GIS operations, supported OS/hardware minima, performance budgets, and proprietary rights/feasibility. Resolve through evidence and explicit acceptance updates in these two planning files. Completion requires capability-level evidence and closed gates, not just a populated CSV.

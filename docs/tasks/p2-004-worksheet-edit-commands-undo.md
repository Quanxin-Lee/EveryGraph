## Scope and acceptance

Objective: implement cell, row and column editing as revision-checked commands over immutable dataset versions, with typed validation, stable identities and undo/redo through the P1-004 kernel. This is the write path that the virtual table and formula engine consume.

P2-002 already ships `data.worksheet_change_rows`, which publishes successor versions and a revised row domain that **the caller** built and staged as drafts. What this task adds is the editing semantics itself: commands that state what the user did — insert, delete, move, resize, set, paste, change type — and build the revised row domain, the successor chunks and the successor versions **inside** the revision-checked transaction, with the typed, unit and missing-value validation and the value-preserving copy that go with them. A table view or formula engine therefore issues one typed command instead of assembling immutable payloads. P2-002's public interfaces are consumed, not edited: `modules/data/include/everygraph/data/commands.hpp` and `modules/data/src/commands.cpp` are untouched, which is why the new family is its own header and translation unit under the `commands/` directories this task's allowed files name.

Allowed files and interfaces: new command sources under `modules/data/src/commands/`, public headers under `modules/data/include/everygraph/data/commands/`, tests under `tests/data/commands/`, the module/test CMake entries required by the P1-011 topology, the `docs/engineering/development.md` refresh designated on release, and this record. The P1-004 command kernel and P2-002 data model are consumed through their public interfaces.

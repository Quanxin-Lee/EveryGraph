## Scope and acceptance

Objective: provide one authoritative allocation point for new task IDs and task-board rows, independent of which agent executes P0-000. The task board plus this record are the real-time source of truth; chat messages, agent memory and branch names are not.

P0-000 is a standing coordination task. It may be executed by different agents over time. Each executor must read the current board, this record and the target task record before allocating anything, and must record its own agent/session label in the Contributions table.

Allowed files and interfaces: this record and the task-board rows P0-000 allocates or maintains. P0-000 may add a board row for a new task and update its own P0-000 row. At allocation, P0-000 creates only the initial record scaffold for a new task: metadata, scope, dependencies, allowed files and acceptance. Once an executor is assigned, only that executor may edit the record; P0-000 never edits an active task record. A scaffold that still has no executor is part of allocation, so P0-000 may revise or cancel it while that remains true, records the revision as allocation in the Contributions table, and stops the moment an executor exists. P0-000 may also update the top-level exclusive task-ownership text in AGENTS.md when the user directly requests that governance change; that is a shared-file edit, not a cross-task edit.

Out of scope: product implementation, executing another task, accepting another owner's task, editing another owner's task record, dependency installation, Windows/CI execution, signing, push or publication.

# ADR-0006: The macOS P1 Entry Gate with Four Named Release Gates

- Status: accepted qualification-sequencing decision for the P1-to-P2 transition. It changes what blocks starting P2 engineering, not what blocks release or distribution, and it claims no pass for any gate it defers.
- Date: 2026-11-01.
- Decision owners: project owner (the 2026-11-01 delegation), recorded by EveryGraph Lead under P0-020.

## Context

[P1-013](../tasks/p1-013-p1-exit-verification.md) graded the macOS P1 exit **not passed** on 2026-11-01: of 14 exit rows, 9 pass, 3 are partial (E2c high-DPI, E6c the recipient rebuild, E6d notices and SBOM), 1 is a gap (E2d multi-monitor) and 1 is the deferred Windows gap (E7). Its gap table records G1 to G7 — G1, G2, G4, G5 and G6 as open macOS items, G3 as the checker backlog and G7 as the Windows row that P1-013 itself notes is not a macOS blocker — and its verdict is that no reading of that table makes the exit a pass. That verdict held P2-002 and every later P2 and P3 row blocked.

Three residuals that were code this host can change have since been dealt with. P1-014 makes the `accessibility_focus_native` entry pass in 30 of 30 full desktop sweeps and in 50 of 50 isolated reruns; P1-015's helper leaves `accessibility_ime_native` at 100 isolated release plus 100 isolated debug runs with zero failures and zero skips; and P1-016 refuses an initial document snapshot whose map key disagrees with the stored object identity instead of accepting it. The first two remove the two non-deterministic entries behind gap G2 (`accessibility_focus_native`, P1-014) and gap I1 (`accessibility_ime_native`, recorded by P1-014 and closed by P1-015), which is what made P1-013 grade E1 and E2a a pass only together with a recorded flake, and the third hardens E4, a row P1-013 had already graded pass. Their disclosures stay attached and this decision closes none of them: P1-014 records that its change attributes a transient host activation loss rather than eliminating it, that one release sweep in P1-015's window failed on exactly that precondition message, that one debug sweep failed on `worker_protocol_tests (SIGPIPE)` which belongs to P1-005's lane, and that P1-015's containment of its residual rests on construction because 310 probe runs and 200 further isolated runs captured no natural failing run. The coordinator's re-score of E1 and E2a as unconditional passes rests on three consecutive full `macos-release-desktop` sweeps at 16 of 16, recorded as D8 in the [allocation record](../tasks/p0-000-task-allocation.md).

What remains is not a defect; it is evidence this host cannot produce. `system_profiler SPDisplaysDataType` returns only the built-in `3024 x 1964 Retina` panel with `Main Display: Yes`, so E2c and E2d cannot be evidenced here at all. E6c needs a rebuild that does not reuse the retained `out/vcpkg-installed` install root. E6d keeps `licenseConcluded: NOASSERTION` with no per-file copyright audit and no written corresponding-source offer, which the [license policy](../engineering/licensing-and-dependencies.md) still lists as open obligations. Windows x64 stays deferred with zero evidence under [ADR-0005](ADR-0005-platform-sequencing.md). Holding P2 until those close blocks engineering on hardware that does not exist here, and none of them is a prerequisite for the P2 typed-data, import and persistence work.

## Decision

1. The macOS P1 exit is an **entry gate** for starting P2 engineering, and that gate is satisfied at this revision. What satisfies it is the evidence P1-013 recorded as passing, read with the three code changes above and their disclosures intact: the native macOS arm64 build with declared minimum-version evidence, the keyboard, focus-order and single-method IME workflows, no Qt in the foundation and application interfaces, command-driven create/edit/undo on fake domain fixtures, the worker handshake, cancellation and crashed-child cases, and the local `.app` bundle from the pinned dynamic Qt graph verified under an ad-hoc hardened-runtime signature with the LGPL library-replacement experiment recorded. E6a's and E6b's recorded scope limits — deploy-and-sign staging on the same host and install root, and the library-validation entitlement trade-off — are part of what this item accepts, not things it re-grades.
2. The four residual items are **release and distribution gates**. They stay open, unclaimed and named, each with the condition that closes it:
   - **Physical display qualification** — rows E2c and E2d, gap G1, owner P1-008. Closed by a run on a host with two physical displays that performs a real display-mode change and a hot-plug and moves a real decorated window between panels, recorded in the P1-008 record. Synthetic `QScreen` rectangles and a `QT_SCALE_FACTOR` on one Retina panel do not close it.
   - **Cold-cache recipient rebuild** — row E6c, gap G5, owner P1-012. Closed by `packaging/macos/rebuild_from_source.sh` completing on a machine without the retained `out/vcpkg-installed` install root, recorded in the P1-012 record. A run that reuses that root reproduces the deploy-and-sign step, not the graph rebuild.
   - **License and notice clearance** — row E6d, gap G5, owner P1-012 under the license policy. Closed by everything the policy's Open-obligations list still names, not by one item of it: a per-file copyright and license audit of the Qt sources actually compiled into the shipped libraries, a written corresponding-source offer carrying the retention period the selected license requires, a release-scope SBOM covering distributed files and build flags with a conclusion that replaces `NOASSERTION` — P1-012's bundle inventory is generated output under the ignored `out/` tree, not a committed release SBOM — and legal review. Flipping the SBOM field alone closes nothing.
   - **Windows x64** — row E7, gap G7, owners P1-002 and P1-010. Closed by a Windows x64 host or authorized CI running the same probe and shell suite under ADR-0005's revisit trigger; no macOS result is inherited as Windows coverage. P1-013 records that although this is not a macOS P1 blocker, it blocks `EG-ADD-016`'s own acceptance wording, which asks for the same smoke suite on both platforms, and the license policy's open Windows triplet resolution belongs here.
3. A screen reader has never run against this tree. The [development guide](../engineering/development.md) limits list states that no screen reader (VoiceOver or other) was run and no WCAG audit of a complete product was performed, and every recorded accessibility run logs `accessibilityActive: false` from the `initTestCase` probe at `apps/desktop/tests/accessibility_tests.cpp:453-458`, so item 1 covers the scripted `QAccessible` walk and the deterministic focus and IME entries — it does not qualify accessibility for release, and that stays with P1-008.
4. This decision does not say that E2c, E2d, E6c or E6d passed, that accessibility is fully qualified or that the license position is cleared. The P1-013 finding that the exit does not pass stays as recorded; what changes is what those rows block.
5. Nothing is superseded. ADR-0005's Windows deferral, P1-013's verdict and gap table, P1-012's documented library-validation trade-off (gap G4) and the never-run static-analysis tools (gap G6) stay exactly as their own records state them.
6. No acceptance criterion, minimum platform, license statement, packaging script or traceability row changes. The [roadmap](../planning/development-roadmap.md) section 3 P1 exit column is rewritten to separate the entry gate from the release gates in one sentence, naming each deferred item rather than deleting it.
7. P2 engineering may start under item 1, and any release, distribution or publication act stays gated by items 2 and 3. This decision sets no P2 phase exit: P2-012's own criteria remain P2-012's to meet, the Phase-0 exit stays partial under P0-015's verdict, and the roadmap's full-capability milestone is untouched. Board rows are released by P0-000, not by this ADR.

## Alternatives

- **Declare a flat P1 pass.** Rejected: E2c, E2d, E6c and E6d are recorded as partial or gap, so a pass would assert that a physical display, a cold-cache machine, a clean environment, a license position and Windows are qualified when no artifact supports it. AGENTS.md section 10 requires stating the open gates instead of inventing facts.
- **Keep P2 closed indefinitely.** Rejected: these gates cannot be closed on this host — one display, no Windows x64 host, no authorized CI — so holding the data-model lane buys no evidence and only defers work that does not depend on that evidence.
- **Weaken the four criteria** — accept simulated `QScreen` geometry as multi-monitor coverage, or count the retained-install-root run as a recipient rebuild. Rejected: P1-013 refused both readings, and AGENTS.md section 0 rule 11 forbids weakening a criterion to make a failure disappear.
- **Drop the deferred items from the roadmap exit column.** Rejected: that silently drops approved scope; the items stay named in the rewritten sentence and in this ADR with an owner and a closing condition each.

## Consequences

- The P2 lane opens on a documented basis instead of a paragraph inside a coordination record, and each release gate keeps an owner, a row reference and a condition, so none is lost by the move.
- Unverified risk carries forward by design: display and multi-monitor behavior, cold-cache reproducibility, license and notice compliance, and Windows. No release, distribution or publication act may imply any of them is settled, and status documents must keep describing them as open gates.
- Accessibility evidence stays narrower than the entry gate's keyboard and IME workflow item suggests: one input method on one line edit, no screen reader, no WCAG pass.
- Sequencing cost: a later display, packaging or licensing finding can still force rework of UI surfaces that P1 qualified only on simulated geometry and one built-in panel.

## Revisit triggers

Re-score this decision when two physical displays plus a real display-mode change and hot-plug run are recorded; when `rebuild_from_source.sh` completes without the retained install root; when the whole license Open-obligations list is closed — the per-file audit, the written corresponding-source offer, a committed release-scope SBOM with a non-`NOASSERTION` conclusion and legal review; when a Windows x64 host or authorized CI runs P1-002 and P1-010; when a screen-reader pass is recorded; or before any release, distribution or publication step — at which point items 2 and 3 become blocking again. A superseding decision, not a reinterpretation of this one, is the route to closing any of them.
